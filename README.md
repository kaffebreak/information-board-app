# 防災・交通情報モニタ

風向・風速画面を追加しました。既存の防災画面は `http://127.0.0.1:8765/`、
風向・風速画面は `http://127.0.0.1:8766/` です。

## 風向・風速ボード

`python kaze_board.py`（Windowsでは `py -3 kaze_board.py` も可）で単独起動できます。
`start_board.bat` は `launch_boards.py` 経由で有効なサーバーを起動し、各サーバーが応答したものから
Edgeのキオスク画面を開きます。各系統は独立して待つので、片方の取得遅延で他方の画面が止まることはありません。
サーバー停止時は10秒後に再起動します。Edgeのプロファイルは画面ごとに分けています。
ログは防災側が `board.log`、風向・風速側が `kaze_board.log` に出力します（各1MB・バックアップ3世代）。
Windowsでのローテーション競合を避けるため、ファイルは共有しません。

| 設定項目 | 初期値・意味 |
|---|---|
| `enable_wind` | `true`。`false` にすると防災画面だけ起動（風向・風速サーバーと画面の起動をスキップ） |
| `wind_port` | `8766`。防災ボードと別のポート |
| `wind_interval` | `60`。データ取得間隔（秒、最短15秒）。観測そのものは名古屋15分、四日市30分 |
| `wind_caution_ms` | **`10` m/s**。依頼者指定の注意ライン。固定軸の範囲内（0より大きく20以下） |
| `wind_window_position` | `null`。風向風速画面の位置。左モニタなら例として `[-1920, 0]`。実機の配置に合わせて後で設定 |
| `bousai_window_position` | `null`。防災画面の位置。例 `[0, 0]` |

設定は `config.example.json` を `config.json` にコピーして変更します。
防災画面だけ起動する場合は `"enable_wind": false`、両画面なら `"enable_wind": true` にして
`start_board.bat` を実行します。省略時は `true` です。文字列の `"false"` ではなく、JSONの `false` を指定してください。
この設定は次回の起動対象を選ぶもので、すでに動いているサーバーや画面は終了しません。
単独起動の `python kaze_board.py` には適用しません。

終了するときは `stop_boards.bat` を実行します。防災・風向のサーバー、自動再起動の監視プロセス、
起動待ちのランチャー、専用Edge画面を終了します。`enable_wind` が `false` でも、起動済みの風向画面は終了対象です。
このフォルダーの実行パスと `.edge-bousai` / `.edge-wind` プロファイルを確認して終了するため、
通常のEdgeや他のプロジェクトのPythonは対象にしません。すでに終了済みでも実行できます。
このバッチは停止用で、二重起動を防ぐ起動ロックはまだありません。

手動でサーバーを起動する場合、終了バッチから識別するにはスクリプトを絶対パスで指定してください。
相対パスだけで単独起動したプロセスや、更新前の `run_server.bat` は所属を確定できない場合があるため、
元のターミナルで Ctrl+C して終了してください。今回の `start_board.bat` / `run_server.bat` は絶対パスを使います。
停止に失敗した場合はエラーを表示します。起動時と同じ権限で終了バッチを実行してください。
位置が未設定の場合はWindowsの既定位置に開くため、2画面が重なることがあります。
モニタ番号から座標を推測せず、Windowsの画面配置で確認してください。実機の3画面への配置は未検証です。
1920×1080のレイアウトを縦横比を保って画面内に収めます。フォント・色は防災ボードと同じです。

名古屋港高潮防波堤中央堤東端と四日市防波堤信号所の観測を表示します。

- 「風弱く」は正常な観測で、欠測とは区別します。グラフに限り0として表示します。
- 6時間最大・平均は**数値のある観測のみ**が対象です。「風弱く」と欠測を除外し、平均欄に数値観測件数／予定件数を表示します。全件が非数値なら統計は「—」です。最大瞬間風速ではありません。
- 欠測・観測間隔を超える空白は線を途切れさせます。四日市は30分値のまま表示します。
- 風配図の母数は風向と数値風速が揃った観測だけです。`kaze_history.json` に24時間分を保存し、実際の集計期間を注記します。再起動でも引き継ぎます。外周15%を超える方位は外周で止め、△を添えます。
- 名古屋は20分超・四日市は35分超で「取得再試行中」、それぞれ35分超・65分超で「判定できません」。古い数値は灰色で残します。
- 通信失敗時は前回値を保持し、画面の通信断表示と観測時刻の経過表示を継続します。
- 注意ライン以上の現在風速は黄色。グラフの縦軸は0〜20 m/s固定で、20超は上端に印と最大値を表示します。

表示確認用URL（実データや履歴には書き込みません）：

- `http://127.0.0.1:8766/?demo=normal`：弱風と通常値
- `http://127.0.0.1:8766/?demo=1`：弱風・古い値・注意ライン超過を同時表示
- `http://127.0.0.1:8766/?demo=high`：新しい観測が注意ラインを超える表示

データ処理の検証は `python -m unittest -v test_kaze_board`。
画面の回帰確認は開発環境の Playwright と Edge を使い、`python -m unittest -v test_board_layout`。
1920×1080・1280×720の通常／警報時に、長い詳細文でも全7路線の状態と文字サイズが保たれることを確認します。
実データの確認は `python -c "import kaze_board as k; print(k.src_nagoya())"` で行えます。

データ源： [名古屋](https://www6.kaiho.mlit.go.jp/nagoyako/kisyou/nagoyako_bw.html)、
[四日市](https://www6.kaiho.mlit.go.jp/04kanku/yokkaichi/yokkaichiko_bkw_lt/kisyou/index.html)。
2026-09-16の実HTMLで両局25行、名古屋の風向・風速が空欄の欠測行、`風弱く`、単位のspan要素を確認。
四日市の共通配下への参照はグラフGIFのみで、両局の履歴を取得できる共通JSONは確認できなかったためHTML表を使用しています。
「風弱く」の数値閾値や個々の観測の平均時間は未確認で、独自に推定していません。
風力の換算は[気象庁の風力階級表](https://www.jma.go.jp/jma/kishou/know/yougo_hp/kaze.html)に基づきます。

---

モニタに常時表示する一画面ボードです。スクロールもクリックも使いません。

鉄道欄は路線名と運行状態を優先します。長い詳細文は列ごとに3行→1行→非表示と調整し、
詳細文の長さを理由に地下鉄などの文字を縮小したり、路線を「ほか○件」にまとめたりしません。
詳細全文の常時表示は保証しません。表示路線を増やした場合は実機で収まりを確認してください。

## 構成

| ファイル | 役割 |
|---|---|
| `bousai_board.py` | 各機関からデータを集めて、表示用ページとまとめたJSONを配信するサーバー |
| `bousai_board.html` | 全画面表示のページ（15秒ごとに自動更新） |
| `config.json` | 表示路線、地図キー、手書きメモなどの設定。APIキーを書くファイルなのでgitには含めません（`config.example.json` をコピーして作ります。無くても既定値で動きます） |
| `config.example.json` | `config.json` の見本 |
| `start_board.bat` | サーバー起動とブラウザ全画面表示をまとめて行う |
| `run_server.bat` | サーバーが止まったとき自動で再起動する（start_board.bat から呼ばれる） |

## 準備（初回だけ）

1. Python 3.9 以上をインストールします。追加ライブラリは不要です。
2. このフォルダを表示用PCの任意の場所に置きます（例: `C:\bousai_board`）。
3. `start_board.bat` をダブルクリックします。Edgeが全画面で開けば完了です。
   全画面を抜けるときは `Alt + F4` を押します。

表示の確認だけしたいときは、ブラウザで `http://127.0.0.1:8765/?demo=1` を開いてください。
警報が複数出て路線が止まった状態をダミーデータで表示します。

## 起動時に自動で表示する

1. `Win + R` で `shell:startup` と入力し、スタートアップフォルダを開きます。
2. `start_board.bat` のショートカットをそのフォルダに置きます。

あわせて、Windowsの設定で「スリープ」「画面の電源を切る」を「なし」にしてください。
自動ログオンにしておくと、停電後の再起動からそのまま表示まで戻ります。

## 設定（config.json）

| 項目 | 内容 |
|---|---|
| `jr_lines` | 表示するJR東海の路線。JRサイトの表記で書きます。東海道線だけは `東海道線(豊橋～米原)` のように区間付きです。 |
| `subway_lines` | 表示する地下鉄路線。名城線と名港線は交通局のデータ上ひとつなので、1行で表示します。 |
| `meitetsu_lines` | 表示する名鉄の線区（初期値：名古屋本線、河和線、常滑線） |
| `quake_hold_hours` | 地震と長周期地震動を発生から何時間表示し続けるか（初期値24） |
| `enable_route23` | 国道23号欄の表示（保留中のため初期値 `false`） |
| `route23_notes` | 国道23号欄に常時表示するメモ（`enable_route23` が `true` のときだけ使います） |
| `google_maps_api_key` | Google Maps のAPIキー。入れると東海〜四日市の交通状況地図が表示されます。空欄なら地図は出ません。キーは表示ページに埋め込まれるので、`host` を `127.0.0.1` 以外にして他のPCから見られるようにする場合は、Google側でキーにHTTPリファラ制限を付けてください。 |
| `isewangan_east` / `isewangan_west` | 伊勢湾岸道の監視区間の両端 |

設定を変えたら、サーバーのウィンドウを閉じて `start_board.bat` を実行し直してください。

## 発令条件の判定方法

| 画面の枠 | 条件 | 判定に使うデータ |
|---|---|---|
| 地震 | 愛知県（東部・西部）、三重県北部・中部で震度5弱以上 | 気象庁 地震情報（震度の細分区域 450/451/460/461） |
| 地震 | 同じ区域で長周期地震動階級3以上 | 気象庁 長周期地震動に関する観測情報 |
| 津波 | 伊勢・三河湾または愛知県外海に大津波警報（予想最大波3m超） | 気象庁 津波警報・注意報 |
| レベル5特別警報 | 愛知県全域、三重県北中部にレベル5の氾濫・大雨・土砂災害・高潮特別警報 | 気象庁 警報（2026年5月からの新しい形式） |
| 特別警報（気象） | 同じ区域に暴風・波浪・暴風雪・大雪の特別警報 | 同上 |
| 全国の地震 | 全国どこかで震度6弱以上 | 気象庁 地震情報 |

- 条件に当てはまった枠は赤くなり、画面上部の帯も赤に変わります。
- 津波警報・津波注意報と、レベル4の危険警報は、黄色の参考表示です。発令条件には数えません。
- データが取れていない枠には「データ取得遅延」と出ます。この表示のときは「該当なし」を信用しないでください。

## 分かっている制約

- **国道23号**：保留中です。取得処理は残してあり、`enable_route23` を `true` にすると名古屋国道事務所の規制・緊急情報が出ます（事故・渋滞の即時情報は含みません）。
- **名鉄の線区別判定**：「路線」欄の線区名で判定し、「理由」の先頭の線区名で、その線区で起きた事由か他線区からの波及かを分けて表示します。波及のときは「三河線 人身事故の影響」のように1行で出し、発生場所は下に1回だけ出します。
- **名鉄・あおなみ線**：データ形式がなくページの文章から読み取っています。サイトのデザインが変わると取れなくなることがあります。そのときはフッターに「取得できていません」と出ます。
- **夜間の表示**：各社のサイトやデータが出している内容に合わせます。JR・地下鉄・あおなみ線は夜間も「平常運転」を出しているのでそのまま表示します。名鉄は0:31〜4:59に「提供時間外」になるので「情報提供時間外」と表示します（異常情報が残っていればそちらを表示）。JRのサイトがメンテナンスで提供を止めているときは「情報提供停止中」と出します。
- **東海道新幹線**は対象外です。
- **伊勢湾岸道の渋滞**：「名港中央IC付近を先頭に 5km」「通過 25分（湾岸弥富IC→名港中央IC間）」の形で出ます。NEXCO中日本が配信しているのは渋滞の先頭位置・長さ・通過時間で、渋滞の末尾がどのICかは配信されていません。
- 各社サイトの非公式な利用です。仕様変更で動かなくなった場合は、該当の取得処理（`src_○○` 関数）の修正が必要です。
